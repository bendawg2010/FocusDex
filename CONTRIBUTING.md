# Contributing to FocusDex

> The Animal Crossing of productivity. The Pokedex for your focus sessions. Welcome to the Notchyverse, trainer.

Hey 🐾 — thanks for poking around. FocusDex is MIT-licensed, free forever, and made out of stubborn love for the idea that focus should feel like an adventure, not a chore. If you've found a bug, want to draw a creature, or have an idea for a Gym Leader, you're already one of us.

There's no contributor hierarchy here. No "core team." Just Notchy, the creatures, and whoever shows up. ✨

---

## What this project is

FocusDex is a tiny menubar app for macOS that turns a Pomodoro timer into a creature-catching journal. You focus, you earn Pokeballs, you spawn and catch creatures on your breaks. Every creature is hand-designed and lives in a 147-strong Notchyverse story bible.

It is intentionally:

- **Cozy, never punitive.** If you break a streak, the app doesn't shame you. Notchy just blinks and waits.
- **Generous.** Catches are easy. The hard part was the focus, not the throw.
- **Local-first.** Your data lives on your machine. No accounts, no telemetry, no dark patterns.
- **MIT, forever.** If anything in here is useful to you for a different project, take it. That's the deal.

If a PR fights any of those three principles, we'll talk it through together before merging — but please don't take a "let's discuss" as a no. The vibe is the product. Anything that protects the vibe is welcome.

## Setting up locally

You'll need macOS 14+ and Xcode (the command-line tools are enough for builds, but Xcode is nicer for editing).

```bash
# 1. Clone
git clone https://github.com/bendawg2010/FocusDex.git
cd FocusDex

# 2. Install xcodegen (one-time, generates the .xcodeproj from project.yml)
brew install xcodegen

# 3. Build
./scripts/build.sh

# 4. Open the app
open build/DerivedData/Build/Products/Release/FocusDex.app
```

That's it. FocusDex will appear in your menubar as a little paw print 🐾 — click it.

If you'd rather work in Xcode while iterating: run `xcodegen generate` once, then open `FocusDex.xcodeproj` and hit ⌘R. Just remember the project file is generated — when you add a new `.swift`, you don't need to fiddle with the Xcode sidebar. `xcodegen` will pick it up next time you run it.

## Design system

Everything visual flows through three files. Please don't reinvent these — extend them.

- **`App/Theme.swift`** — the brand palette, gradients, and the `PrimaryGradientButtonStyle`, `OrbBackground`, and `AnimatedGradientText` primitives. If you need a new color, add it here. If you need a one-off color, ask yourself one more time if you really do.
- **`App/Pixels.swift`** — the `PixelArt` Canvas renderer and the standard pixel palette character map (matches the design bundle's PAL exactly).
- **`App/UISprites.swift`** — `TypeBadge`, the hexagonal type chip, and the per-`CreatureType` gradient mappings.

### Brand palette

| Token              | Hex       | Use                                  |
|--------------------|-----------|--------------------------------------|
| `Theme.pink`       | `#FF6B6B` | Primary accent, streak flame         |
| `Theme.magenta`    | `#C147FF` | Primary accent, glow                 |
| `Theme.blue`       | `#47A0FF` | Cool accent, focusing-state          |
| `Theme.mint`       | `#2EE6A0` | Success, "Code" type, tip-jar accent |
| `Theme.yellow`     | `#FFD960` | Highlight, "Sun" type                |
| `Theme.bgDeep`     | `#06010f` | Popover background (deep)            |
| `Theme.bgCard`     | `#0c0420` | Popover background (lifted)          |

Gradients you should reach for before mixing your own:

- `Theme.titleGradient` — the signature five-color title sweep
- `Theme.primaryGradient` — pink → magenta, for CTAs
- `Theme.focusGradient` — mint → blue, for active-session UI
- `Theme.popoverBackground` — the standard dark backdrop

There's also a `.brandGlow(_:radius:)` view modifier for the soft drop-shadow look used everywhere.

## Adding a creature

Creatures live in `App/Data/Creatures_*.swift`, one file per family. Each file is just a `static let` extension on `Creature` returning `[Creature]`. To add one:

1. Pick the right family file (e.g. a new coffee creature goes in `Creatures_TimeOfDay.swift` or `Creatures_FoodBeverage.swift`, depending).
2. Pick the next free `id` (dex number). Check `99-MASTER-DEX.md` in `FocusDex-Designs/` for the canonical numbering.
3. Add a `Creature` with all required fields:

```swift
Creature(
    id: 42,                          // dex number (Int)
    name: "Snoozecub",               // Title-case, no spaces, "Cub/-let/-ling" suffix vibes
    primary: .dream,                 // CreatureType — see App/Features/Dex/Creature.swift
    secondary: .moon,                // Optional CreatureType?
    rarity: .uncommon,               // .common, .uncommon, .rare, .legendary, .mythic
    hp: 70, fp: 80, sta: 85, spd: 55,
    signatureMove: "Pillow Talk",    // Short, evocative, often a real-world phrase pun
    blurb: "A drowsy cub that...""   // 1–2 sentence creature description, present tense
)
```

The `CreatureType` enum is defined in `App/Features/Dex/Creature.swift`:

```
.code  .art  .doc  .sound  .sun  .moon  .dream  .spark
.zen   .caffeine  .storm  .glitch  .spirit  .pixel  .time
```

A few tone notes for the blurb:
- Notchyverse creatures are *characters*, not stat blocks. Give them a tiny life — what they want, where they nest, what they do when nobody's watching.
- Cozy. Soft. Slightly poetic. Never edgy, never punitive.
- Reference real-world programmer/creator life with affection.

If the creature doesn't yet have art in `FocusDex-Designs/`, that's fine — open a PR with the data anyway and mention it. We'll sketch a pixel sprite to go with it.

## Adding a screen

The convention is **one folder per feature**, with the SwiftUI view files alongside any helpers and stores:

```
App/Features/<feature-name>/<ViewName>.swift
```

For example, adding a `Battles` feature would mean `App/Features/Battles/BattleView.swift`, plus maybe a `BattleManager.swift` alongside it.

### Environment objects available

`AppDelegate` injects two environment objects at the popover root:

- `@EnvironmentObject var focus: FocusManager` — current session state, durations, ball balance, streak.
- `@EnvironmentObject var dex: DexStore` — caught creatures, encounter history.

You can read either from any view inside the popover without re-passing.

### Tab integration

If your screen is a new top-level tab, add it to the `ContentView.Tab` enum in `App/ContentView.swift` and the `switch tab` block right below. The `TabBar` will pick it up automatically — just give it an SF Symbol name in the `icon` computed property.

### Tone for copy

Empty states, error states, and notifications should sound like a friend who's rooting for you. Some examples that already ship:

- *"Ready to focus?"* (not "Begin session")
- *"Pick a duration. Catch what you spawn."* (not "Configure timer")
- *"Welcome, trainer."* (not "Get started")

If it sounds like a checkout flow, rewrite it. If it sounds like Notchy is gently nudging you, it's right.

## Building & running

```bash
./scripts/build.sh
```

That's the whole story. The script:

1. Verifies `xcodegen` is installed.
2. Runs `xcodegen generate` to (re)create `FocusDex.xcodeproj` from `project.yml`.
3. Runs an unsigned Release build into `build/DerivedData/`.
4. Prints the path to the built `.app`.

For packaging a DMG (relevant if you're cutting a release), `./scripts/build-dmg.sh`. For Sparkle appcast signing, see `scripts/sparkle/`.

## Testing

We don't have tests yet. That's not a brag — it's just where we are. The app is small enough that hand-poking it covers the surface area for now.

**If you're adding tests** (which would be lovely), please use XCTest under a `FocusDexTests/` target. You'll need to add the target to `project.yml` so `xcodegen` picks it up. Aim small: `FocusManagerTests`, `DexStoreTests`, `CreatureDataTests` (e.g. "every creature has a unique id, every id is contiguous"). Don't try to cover the whole app at once — a few sturdy unit tests will pay for themselves.

## Pull request etiquette

- **Small and focused.** One creature family, one screen, one bug — not all three in one PR. Easier to review, easier to revert if Notchy frowns.
- **Reference the design package.** If your change is visual, link the corresponding file in `FocusDex-Designs/` (e.g. *"matches `02-time-of-day.md` entry #15"*). If there's no canon yet, say so and propose something — we'll riff together.
- **Match the tone.** Read a couple of existing creature blurbs and UI strings before you write yours. The voice is the product.
- **Don't hand-edit `FocusDex.xcodeproj/`.** Edit `project.yml` instead. The `.xcodeproj` is regenerated by `xcodegen`.
- **Keep `Theme.swift`, `Pixels.swift`, and `UISprites.swift` as the single source of visual truth.** If you find yourself hardcoding a hex value in a view, that's a hint to add it to the palette instead.
- **Branch naming is whatever.** `feature/`, `fix/`, `creature/snoozecub` — all fine. Just be descriptive.
- **Commit messages** should be short and honest. Past-tense is fine. Emoji are welcome but not required.

If you're not sure whether something fits, open a draft PR or an issue and we'll figure it out. There's no wrong way to show up.
